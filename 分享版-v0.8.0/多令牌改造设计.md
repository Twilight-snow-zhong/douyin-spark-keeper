# 多令牌改造设计（`多令牌版` · v0.7.0）

> 目标：**一个端口、一套程序、多个令牌 → 多个互相隔离的「工作区」**

> ⚠️ **用户要求：本目录只做本地开发，不打包、不部署到服务器。** 如需上线，另行确认。
> 这样你和朋友各自一个令牌，进去只看到自己的账号、好友、日志与通知配置。
>
> 本目录是从 `服务器版`（v0.6.6）复制出来的**独立开发目录**：
> 改它不会影响 `服务器版`，更不会影响你服务器上正在跑的 `/root/douyin-spark`（那要你手动 scp 才会变）。
> 如果这个改造失败，直接删掉本目录即可，稳定版毫发无损。

---

## 1. 名词

| 名词 | 含义 |
|---|---|
| **工作区（workspace）** | 一套完整的数据：账号、登录态、好友、消息模板、定时、日志、通知配置、图片库 |
| **默认工作区** | `default`，就是你现在用的那套数据（**路径不变**） |
| **令牌** | 访问某个工作区的唯一钥匙；不同令牌 = 不同工作区 |

---

## 2. 零迁移原则（最重要的一条）

**改造上线后，你现有的数据一个字节都不用动、不用重新扫码登录。** 做法：

| 工作区 | 数据根目录 |
|---|---|
| `default`（你的） | **沿用现状**：`data/accounts/`、`data/config.json`、`data/emojis/`、`data/logs/` |
| 新增工作区（朋友的） | `data/ws/<id>/accounts/`、`data/ws/<id>/config.json`、`data/ws/<id>/emojis/`、`data/ws/<id>/logs/` |

并且：**`data/tokens.json` 不存在时，行为与 v0.6.6 完全一致**（`.env` 里的 `AUTH_TOKEN` = 默认工作区）。
→ 也就是说，这个改造是**纯增量**的：老部署即便不动配置文件，也不会崩、不会串数据。

---

## 3. 令牌表 `data/tokens.json`

```json
{
  "version": 1,
  "tokens": {
    "a1b2c3...（32 位随机十六进制）": {
      "name": "我",
      "ws": "default",
      "created": "2026-09-30T13:00:00"
    },
    "9f8e7d...（32 位随机十六进制）": {
      "name": "朋友1",
      "ws": "ws_9f8e7d",
      "created": "2026-09-30T13:05:00"
    }
  }
}
```

* 文件写入时 `chmod 600`（与 `.env` 同等敏感度）
* 明文存储（与 `.env` 现有做法一致），这样界面里能「查看/复制/轮换」令牌，不必让用户自己记
* 一个工作区可以有多把令牌（方便"换一把但旧的先留着"过渡）

---

## 4. 认证流程

1. 请求带 `X-Auth-Token`
2. `resolve_token(token)`：
   - `tokens.json` 存在 → 查表，命中就返回对应 `ws`；未命中 → 401
   - `tokens.json` 不存在 → 拿 `.env` 的 `AUTH_TOKEN` 比对，命中即 `default`（**老行为**）
3. 所有业务接口通过依赖拿到「工作区根目录」，再用它拼账号目录/配置/日志路径
4. **本机（回环）特权**：沿用 `_client_ip()` 的判断 —— 只有本机来源才能"首次设置令牌/新建工作区"，公网来源必须带有效令牌
5. 错误一律返回 `{"detail":"访问令牌不正确"}`，**不泄露**"这个令牌存在但工作区被删了"之类的信息

### 新增接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/workspaces` | 列出工作区（名称、账号数、创建时间；**不返回完整令牌**，只返回后 4 位用于辨认） |
| POST | `/api/workspaces` | 新建工作区 `{name}` → 返回**一次性明文令牌**（并写入令牌表） |
| POST | `/api/workspaces/{ws}/rotate` | 轮换该工作区令牌 → 返回新明文令牌（可保留旧令牌 N 分钟，默认立即失效） |
| POST | `/api/workspaces/{ws}/rename` | 改名 |
| DELETE | `/api/workspaces/{ws}` | 删除（**default 不可删**；需带 `?confirm=<工作区名>` 二次确认；数据目录改名到 `data/ws/_deleted_<时间>/` 而不是真删，可反悔） |
| GET | `/api/me` | 当前令牌对应的工作区信息（名称、账号数） |

## 5. 代码改动清单

| 文件 | 改动 |
|---|---|
| **新增** `core/workspace.py` | 令牌表读写、`resolve_token()`、`ws_paths(ws)`、创建/删除/轮换 |

| `static/index.html` | 侧栏加「🗂 工作区管理」：列表、新建（显示一次性令牌 + 复制）、轮换、改名、删除；页面其余部分自动只看到自己工作区的数据 |

## 6. 测试计划（每改一处就跑）

**A. 单元测试（`core/workspace.py`）**
- 无 `tokens.json`：`.env` 令牌 → `default`；错误令牌 → None
- 有 `tokens.json`：每把令牌 → 对应 ws；未知令牌 → None；空令牌 → None
- `ws_paths("default")` → 必须是**老的 data 路径**（回归的关键）
- `ws_paths("ws_x")` → `data/ws/ws_x/...`
- 新建/轮换/删除：幂等性、default 不可删、删除是"改名归档"不是真删

**B. 隔离测试（起真实服务）**
- 用 A 令牌创建账号 → 用 B 令牌 `GET /api/accounts` **看不到**
- A 保存通知配置 → B 的配置不受影响
- A 的日志里不出现 B 的账号名
- B 的令牌访问 `/api/workspaces/{A_ws}` → 403/404

**C. 回归测试**
- 不创建 `tokens.json` 时，全部老接口与 v0.6.6 行为一致（401/200 矩阵）
- 老数据（`data/accounts/...`）仍能被正常读取、发送、出日志

**D. 端到端（无头浏览器）**
- 两个令牌分别登录 → 界面各自只显示自己的账号
- 工作区管理页：新建 → 复制令牌 → 用新令牌另开一个浏览器上下文验证

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 某个接口漏带工作区 → 串数据 | P2 逐个接口过 + B 组隔离测试；默认工作区路径不变，老数据最坏也不受影响 |
| 调度器重复跑/漏跑 | 任务 key 用 `ws:acc_id`；启动时重建全部任务；P3 单独测试 |
| 令牌明文存储被读取 | 与 `.env` 一致（本来就明文），文件 `chmod 600`；服务器只有 root |
| 改造后你现有部署要换代码 | **默认工作区零迁移**：只换代码，数据/登录态/配置原样沿用；上线前先在副本上跑完 A~D |
| 改造失败 | 删掉 `多令牌版` 目录即可，稳定版与线上服务毫发无损 |

### 现在就试用（curl）

```bash
# 0) 变量
TOK="你的主令牌"          # 就是 .env 里那把
BASE="http://127.0.0.1:8000"

# 1) 我是哪个工作区
curl -s -H "X-Auth-Token: $TOK" "$BASE/api/me"

# 2) 新建一个给朋友的工作区（返回一次性明文令牌，请立刻发给他）
curl -s -X POST -H "X-Auth-Token: $TOK" -H "Content-Type: application/json" \
     -d '{"name":"老王"}' "$BASE/api/workspaces"

# 3) 列出所有工作区（只显示令牌尾号，不返回完整令牌）
curl -s -H "X-Auth-Token: $TOK" "$BASE/api/workspaces"

# 4) 隔离自检：用朋友的令牌看他的账号（应该只有他自己的）
curl -s -H "X-Auth-Token: 朋友的令牌" "$BASE/api/accounts"

# 5) 轮换某人的令牌（主令牌可代做；换完旧的立刻失效）
curl -s -X POST -H "X-Auth-Token: $TOK" "$BASE/api/workspaces/<ws_id>/rotate"

# 6) 改名 / 删除（删除要二次确认，且是"改名归档"可找回）
curl -s -X POST -H "X-Auth-Token: $TOK" -H "Content-Type: application/json" \
     -d '{"name":"老王的新名字"}' "$BASE/api/workspaces/<ws_id>/rename"
curl -s -X DELETE -H "X-Auth-Token: $TOK" "$BASE/api/workspaces/<ws_id>?confirm=老王的新名字"
```
