### v0.6.6 修复
- **🐛 通知渠道配置保存后被清空（本次部署实测踩到，等于通知永远发不出去）**
  - 根因：`core/config.py` 的 `DEFAULT_GLOBAL_CONFIG["notify"]` **只有 `desktop`**，且 `load_global_config()` / `save_global_config()` 都只搬 `desktop` → 界面配好的 `webhook_enabled / webhook_type / webhook_url` 读写一次即丢
  - 误导表现：界面「保存」提示成功、点「测试」还回绿色"通知功能正常"，但磁盘里永远只有 `{"desktop": false}`，手机收不到推送
  - 修复：补齐默认四项 + 新增 `_norm_notify()` 统一规范化（未知渠道回退 `ntfy`、URL 去空格）
  - 实测（真实服务器）：`PUT → GET → 重启 → GET` 四项保持；`POST /api/notify/test` → `{"results":["webhook（pushplus）✓"]}`
  - 排查手法：`curl -s <地址>/api/global/config -H "X-Auth-Token: <令牌>"`，若只返回 `{"notify":{"desktop":false}}` 即中招
- **🐛 测试通知"什么都没做"却显示绿色成功**
  - 后端在无任何可用渠道时返回空 `results`，前端当成功 → 现在空结果显示**黄色警告**并提示「先点保存，测试读的是已保存配置」；服务器上不再提示"看电脑右下角气泡"，改为「已通过 webhook 推送，请查看手机通知」
- **🐛 后端兜底**：`send_notification()` 无渠道可用时返回明确说明，不再返回空列表
- **🐛 webhook 推送结果不再误报成功（本轮实测又发现的）**
  - 根因：PushPlus / Server酱 对**无效 token、未关注公众号**等错误**也返回 HTTP 200**，错误码只在响应体里；旧代码的判断是 `if '"code":200' not in body and r.status >= 400`（两个条件同时成立才报错）→ 永远不报错
  - 修复：解析响应体，按应用层 `code` 判定（PushPlus `200` / Server酱 `0`），失败时抛出**真实原因**，例如：
    `webhook（pushplus）✗（PushPlus code=903 msg=用户令牌不正确）`
  - 实测：假 token → 正确报 903；真实 token → `webhook（pushplus）✓`
- **🔧 nginx 模板 http2 语法（Ubuntu 22.04 + nginx 1.18 起不来）**
  - 现象：`nginx -t` → `unknown directive "http2"`，服务启动失败
  - 根因：模板写的是 nginx **1.25+** 语法 `http2 on;`；1.18 只认 `listen ... ssl http2;`
  - 修复：`deploy/nginx-douyin-spark-8443.conf`、`deploy/nginx-douyin-spark.conf` 均改为 `listen <port> ssl http2;`

### v0.6.6 文档（`域名与HTTPS部署.md`）

## v0.6.5（群发切换失败修复 + 日志折叠加强 · 个人版 / 服务器版同步 · 已打包）

> 版本号已由 0.6.4 升至 0.6.5。与个人版同版本同步。

### v0.6.5 修复 / 优化
- **🐛 个别好友在群发中固定失败（单独发 / 自动补发却成功）**
  - 根因一：左侧会话列表是**虚拟列表**，视窗外行会从 DOM 卸载；群发中途被点过的会话跳到顶部后，目标行在**上方**，而旧逻辑只在"找不到"时**向下滚**，越找越远 → 固定失败
  - 根因二：搜索兜底会把左侧列表 `display:none`，且失败后不退出搜索态 → 之后**所有**好友点击都报 `Element is not visible`（连带伤害）
  - 修复：`open_contact_by_list()` 先回顶部再逐屏向下扫到列表底部，每屏按**归一化名字**比较、只点**有真实坐标的可见行**（鼠标坐标点击）；`_ensure_list_visible()` 每轮发送前退出残留搜索态（必要时重载私信页）；`search_and_open()` 只用可见结果且无论成败都退出搜索态；好友名里的 NBSP 等异常空白统一归一化
  - 实测：全名单干跑 **14/14 成功**（修复前 13/1）
- **📄 日志折叠判定加强**：日志区实际渲染字体是 monospace，而截断宽度一直按比例字体测量 → 超宽行漏折；现在字体取自 `.log-pre` 的 `getComputedStyle`，并加 `ResizeObserver` + 侧栏切换重测、`\t` 按 8 空格展开、判定只看"行本身是否超宽"
  - 实测：同一批日志（可用宽 826px）真实超宽 8 行、旧规则只判出 6 行；新规则在宽/窄/回宽三种宽度下逐条判定零偏差，折叠项全部硬性单行
- **🔎 失败日志写详细**：切换会话失败记名字转义与归一化、列表可见性/滚动位置/渲染行数/已扫描屏数/命中行数/首尾行/当前会话/是否走过搜索兜底；搜索兜底失败记搜索框内容与可见入口数；媒体段失败记段类型/内容/当前会话/完整模板；扫描超过 1 屏记 INFO
- **📜 日志页取数 400 → 800 行**（后端上限 600 → 1200），失败条目更长后 400 行覆盖不到两次运行
